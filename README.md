# Voice Assistant

Настольное JavaFX-приложение для записи микрофона, системного звука Windows или обоих источников одновременно. Запись сохраняется в WAV-файл. В режимах Stub и OpenRouter API речь распознаётся локально через `whisper.cpp` или удалённо через API OpenRouter, после чего текст можно отправить в тестовый ИИ-сервис или OpenRouter API. Режим OpenRouter Audio отправляет WAV модели напрямую.

## Требования

- Windows с поддержкой WASAPI loopback;
- JDK 25 (64-битный) и настроенная переменная `JAVA_HOME`;
- CMake 3.20 или новее;
- Visual Studio 2022 или Build Tools с компонентом **Desktop development with C++** (MSVC и Windows SDK).
- Для локального распознавания: `whisper-cli.exe` из [whisper.cpp](https://github.com/ggml-org/whisper.cpp) и многоязычная модель формата GGML. Для удалённого распознавания и облачных режимов нужен API-ключ OpenRouter и доступ к сети.

Maven устанавливать отдельно не требуется: в проекте есть Maven Wrapper. Архитектура собранной DLL должна совпадать с архитектурой JVM.

## Сборка и запуск

Если `native\release\WasapiCapture.dll`, `whisper\whisper-cli.exe` и модель уже подготовлены, для повседневного запуска откройте `start.cmd` двойным щелчком. Скрипт проверяет наличие локального Whisper даже при выборе удалённого распознавания или OpenRouter Audio. При первом запуске после сборки `whisper.cpp` выполните из корня проекта:

```powershell
.\prepare-whisper.ps1
```

Скрипт копирует `whisper-cli.exe`, необходимые DLL и `ggml-base.bin` из соседней папки `..\whisper.cpp` в локальную папку `whisper\`. При другом расположении исходников укажите `-WhisperRoot 'D:\путь\к\whisper.cpp'`. Исполняемый файл и DLL в `whisper\` отслеживаются Git, а файл модели `whisper\ggml-base.bin` исключён из Git и должен быть подготовлен отдельно. `start.cmd` сам подставляет локальные пути к Whisper и ищет JDK 25 в `JAVA_HOME` либо в `%USERPROFILE%\.jdks`.

Для первоначальной сборки компонентов выполните следующие шаги.

Откройте PowerShell в корне проекта. Для сборки C++ используйте терминал разработчика Visual Studio с доступными `cmake` и MSVC. Если JDK не определяется автоматически, укажите путь к нему через `JAVA_HOME` (к каталогу JDK, без `bin`): `$env:JAVA_HOME = 'C:\Path\To\jdk-25'`.

Сначала сконфигурируйте и соберите нативную библиотеку:

```powershell
cmake -S native -B native\build
cmake --build native\build --config Release
```

Сборка помещает готовую DLL сразу в `native\release\WasapiCapture.dll`. Этот файл можно хранить в Git; служебные файлы `native\build\`, включая `.lib` и `.exp`, в Git не добавляются. Если CMake по умолчанию выбирает другой генератор или архитектуру, задайте их при конфигурации: `cmake -S native -B native\build -G "Visual Studio 17 2022" -A x64`.

Затем соберите и запустите JavaFX-приложение:

```powershell
.\mvnw.cmd clean compile
.\mvnw.cmd javafx:run
```

Плагин JavaFX в `pom.xml` передаёт приложению путь к DLL через `java.library.path`. Класс `SystemAudioSource` вызывает `System.loadLibrary("WasapiCapture")` при создании сервиса записи, поэтому DLL нужна и для запуска с выбранным режимом «Микрофон». При запуске из IntelliJ IDEA укажите в VM options `-Djava.library.path=<абсолютный путь к native\release>`.

## Сборка Portable-приложения для Windows

Логи записываются в `%LOCALAPPDATA%\VoiceAssistant\logs\voice-assistant.log` (при отсутствии
`LOCALAPPDATA` — в `%USERPROFILE%\VoiceAssistant\logs`). Файл достигает 5 МБ, после чего
архивируется; хранятся пять архивов `voice-assistant.1.log.gz` —
`voice-assistant.5.log.gz`. Уровень по умолчанию — INFO. Для диагностики добавьте
`-Dvoiceassistant.log.level=DEBUG` к параметрам JVM в IDE или строку
`java-options=-Dvoiceassistant.log.level=DEBUG` в секцию `[JavaOptions]` файла
`dist\VoiceAssistant\app\VoiceAssistant.cfg` после упаковки. Для произвольной
конфигурации Logback доступен стандартный параметр JVM
`-Dlogback.configurationFile=<путь к файлу>`.

Portable-версия создаётся через `jpackage` из JDK 25 и запускается двойным щелчком по `VoiceAssistant.exe`, без `start.cmd` и отдельно установленной Java. Для сборки заранее подготовьте `native\release\WasapiCapture.dll`. Папка `whisper\` с `whisper-cli.exe`, `ggml-base.bin` и необходимыми DLL нужна, если планируется локальное распознавание. Точка входа для упаковки — `com.voiceassistant.Launcher`.

Выполняйте команды по порядку в PowerShell из корня проекта.

1. Соберите JAR и скопируйте Maven-зависимости:

   ```powershell
   .\mvnw.cmd clean package -DskipTests
   .\mvnw.cmd dependency:copy-dependencies "-DoutputDirectory=target/dependency"
   ```

2. Подготовьте каталог входных файлов для `jpackage`:

   ```powershell
   New-Item -ItemType Directory -Path target\package-input -Force
   Copy-Item target\voiceassistant-1.0-SNAPSHOT.jar target\package-input\
   Copy-Item target\dependency\*.jar target\package-input\
   ```

3. Создайте приложение без консольного окна (не добавляйте `--win-console`):

   ```powershell
   jpackage `
     --type app-image `
     --name VoiceAssistant `
     --input target\package-input `
     --main-jar voiceassistant-1.0-SNAPSHOT.jar `
     --main-class com.voiceassistant.Launcher `
     --dest dist `
     --java-options '-Djava.library.path=$APPDIR\..\native' `
     --java-options '--enable-native-access=ALL-UNNAMED'
   ```

4. Скопируйте нативную библиотеку WASAPI и, если требуется локальное распознавание, компоненты Whisper:

   ```powershell
   New-Item -ItemType Directory -Path dist\VoiceAssistant\native -Force
   Copy-Item native\release\WasapiCapture.dll dist\VoiceAssistant\native\
   ```

   Если нужно локальное распознавание, дополнительно выполните:

   ```powershell
   Copy-Item whisper dist\VoiceAssistant\whisper -Recurse -Force
   ```

5. Проверьте наличие файлов:

   ```powershell
   Test-Path dist\VoiceAssistant\VoiceAssistant.exe
   Test-Path dist\VoiceAssistant\native\WasapiCapture.dll
   Test-Path dist\VoiceAssistant\whisper\whisper-cli.exe
   Test-Path dist\VoiceAssistant\whisper\ggml-base.bin
   ```

   Первые две команды должны вернуть `True`. Последние две должны вернуть `True`, если вы добавили локальный Whisper. Для запуска перейдите в папку приложения и откройте EXE:

   ```powershell
   Set-Location dist\VoiceAssistant
   .\VoiceAssistant.exe
   ```

Готовая Portable-сборка находится в `dist\VoiceAssistant\`: рядом с `VoiceAssistant.exe` находятся каталоги `app\`, `runtime\`, `native\` и, если скопирован локальный Whisper, `whisper\`. Для переноса необходимо копировать **всю папку**. Поиск Whisper по умолчанию зависит от рабочей директории: если приложение запускается из другой папки, задайте абсолютные пути через `VOICEASSISTANT_WHISPER_CLI` и `VOICEASSISTANT_WHISPER_MODEL`. Проверьте запуск двойным щелчком через Проводник. Для повторной сборки удалите или переименуйте старую папку `dist\VoiceAssistant\` после закрытия приложения.

## Настройка распознавания

Откройте терминал разработчика Visual Studio в корне скачанного [whisper.cpp](https://github.com/ggml-org/whisper.cpp) и соберите программу распознавания:

```powershell
cmake -S . -B build
cmake --build build --config Release --target whisper-cli
```

При генераторе Visual Studio результат находится в `build\bin\Release\whisper-cli.exe`. Затем скачайте [многоязычную модель GGML](https://github.com/ggml-org/whisper.cpp/blob/master/models/README.md):

```powershell
.\models\download-ggml-model.cmd base
```

Скрипт сообщает полный путь сохранённого `ggml-base.bin`; в текущей версии он находится в корне `whisper.cpp`. Модель с суффиксом `.en` предназначена для английского языка и для русской речи не подходит. После этого выполните `prepare-whisper.ps1` из корня `voiceassistant`. Приложение найдёт файлы в папке `whisper\` автоматически.

Если хотите хранить Whisper отдельно, можно вместо этого указать абсолютные пути в переменных окружения **процесса, запускающего приложение**:

```powershell
$env:VOICEASSISTANT_WHISPER_CLI = 'C:\Path\To\whisper.cpp\build\bin\Release\whisper-cli.exe'
$env:VOICEASSISTANT_WHISPER_MODEL = 'C:\Path\To\whisper.cpp\ggml-base.bin'
.\mvnw.cmd javafx:run
```

Для запуска из IntelliJ IDEA с отдельным расположением файлов добавьте эти переменные в Run Configuration. Для локальной папки `whisper\` переменные не требуются, если рабочая директория конфигурации — корень проекта. Приложение само преобразует WAV в моно PCM 16 кГц, который принимает `whisper-cli`; `ffmpeg` не требуется. Локальное распознавание выполняется после остановки записи в фоновом потоке. Первый запуск может занимать больше времени из-за загрузки модели.

В настройках ИИ можно выбрать «Удалённо (API)» для распознавания через OpenRouter. Приложение отправляет сохранённый WAV на `https://openrouter.ai/api/v1/audio/transcriptions` и использует тот же ключ OpenRouter, что и облачные режимы ИИ. Доступны модели `openai/whisper-large-v3-turbo` (по умолчанию), `openai/whisper-large-v3`, `openai/whisper-1`, `openai/gpt-transcribe` и `openai/gpt-4o-transcribe`. Размер WAV ограничен приложением до 25 МБ. Этот способ работает и с режимом Stub: распознавание будет облачным, а генерация ответа — локальной. В режиме OpenRouter Audio отдельная настройка распознавания не используется.

## Использование

1. Выберите источник: **Микрофон**, **Системный звук** или **Микрофон + системный звук**. По умолчанию выбран микрофон.
2. Нажмите «Начать запись», затем «Остановить запись».
3. Путь к сохранённому WAV появится в окне приложения. Для проверки системного звука запустите воспроизведение аудио в Windows во время записи.
4. В режимах Stub и OpenRouter API нажмите «Распознать речь». Приложение использует выбранный в настройках способ распознавания. Результат появится в текстовом поле; при необходимости отредактируйте его.
5. В этих же режимах нажмите «Отправить в ИИ». Ответ выбранного сервиса будет постепенно появляться в поле «Ответ ИИ», где его можно выделить и скопировать уже во время генерации. Строка состояния ИИ показывает ход обработки и возможные ошибки.

Во время записи можно вместо «Остановить запись» нажать «Завершить и отправить в ИИ». В текстовых режимах приложение сохранит WAV, распознает речь выбранным способом и отправит текст в ИИ. В режиме OpenRouter Audio сохранённый WAV отправляется модели напрямую; кнопки «Распознать речь» и «Отправить в ИИ» для этого режима недоступны. Если модель вернёт текст вопроса в ожидаемом формате, он появится в поле «Распознанный вопрос», а ответ — в поле «Ответ ИИ». В текстовых режимах отдельные кнопки позволяют проверить и исправить текст перед отправкой.

На каждом этапе строка состояния показывает текущую операцию. При ошибке цепочка прекращается и сообщает, где она произошла. Если речь не распознана, пустой текст в ИИ не отправляется. Во время автоматической обработки конфликтующие кнопки блокируются; после завершения, ошибки или отмены их состояние восстанавливается. Тестовый ответ формируется локальным `StubAiService`; при локальном распознавании ключ и интернет не нужны.

## Настройки ИИ

Кнопка ⚙ в правом верхнем углу открывает окно «Настройки ИИ». В списке «Режим ИИ» доступны **Stub (тестовый режим)**, **OpenRouter API** и **OpenRouter Audio**. При первом запуске выбран Stub; текущий режим показан рядом с кнопкой. OpenRouter API отправляет распознанный текст в облачный сервис. OpenRouter Audio отправляет записанный WAV напрямую в OpenRouter.

Поле API-ключа скрывает ввод. Сохранённый ключ не подставляется обратно в поле: окно показывает «API-ключ сохранён». Для замены введите новый ключ и нажмите «Сохранить»; пустое поле оставляет прежний ключ. Кнопка «Удалить сохранённый ключ» помечает его к удалению после сохранения. Ключ защищается Windows DPAPI для текущего пользователя и хранится в `%APPDATA%\VoiceAssistant\openrouter-key.dpapi`. OpenRouter API и OpenRouter Audio используют один ключ OpenRouter.

В списке «Модель» для OpenRouter API доступны `openrouter/free` (по умолчанию), `qwen/qwen3-235b-a22b-2507`, `openai/gpt-4.1-mini` и `openai/gpt-5-mini`; для OpenRouter Audio — `openai/gpt-audio-mini` (по умолчанию) и `openai/gpt-audio`. Выбор моделей каждого режима сохраняется отдельно. При выбранном Stub список неактивен. Настройки «Способ распознавания речи» и «Модель распознавания речи» относятся к текстовым режимам; выбор модели доступен при удалённом распознавании. Многострочное поле «Системный промпт» позволяет менять инструкции модели с сохранением переносов строк. Кнопка «Восстановить промпт по умолчанию» меняет только текст в открытом окне; для записи нажмите «Сохранить».

Настройка «Использовать контекст диалога» по умолчанию выключена. При включении можно выбрать глубину от 1 до 10 завершённых обменов. Для текстовых запросов OpenRouter API в контекст включаются прежние текстовые запросы и ответы; для OpenRouter Audio передаются только прежние ответы, хотя аудиомодель может вернуть текст вопроса в текущий запрос.

Режим, модели, способ распознавания, промпт, параметры контекста и размер шрифта ответа сохраняются между запусками в `%APPDATA%\VoiceAssistant\ai-settings.properties`. Размер шрифта ответа меняется кнопками `A−` и `A+` в основном окне (от 10 до 30). «Отмена» или закрытие окна кнопкой Windows отменяет несохранённые изменения настроек ИИ. При ошибке сохранения окно остаётся открытым и показывает сообщение.

Если в старых настройках был выбран DeepSeek API, приложение переключится на OpenRouter API. Для отправки запросов потребуется ключ OpenRouter; прежний файл ключа DeepSeek приложение больше не использует.

Если в старых настройках был выбран OpenAI Audio, приложение переключится на OpenRouter Audio. Для отправки WAV потребуется ключ OpenRouter; прежний файл ключа OpenAI Audio приложение больше не использует.

## Облачные режимы

Для OpenRouter API, OpenRouter Audio и удалённого распознавания получите API-ключ в [настройках OpenRouter](https://openrouter.ai/settings/keys). Откройте ⚙ «Настройки ИИ», введите ключ OpenRouter, при необходимости измените модель и системный промпт, затем нажмите «Сохранить». Для ввода ключа выберите OpenRouter API или OpenRouter Audio; после сохранения можно вернуться к Stub, если нужен локальный тестовый ответ с удалённым распознаванием. Ключ можно заменить или удалить в этом же окне. В облачных режимах ИИ отсутствие ключа проверяется до автоматической остановки записи; при удалённом распознавании в режиме Stub ошибка будет показана на этапе распознавания.

В режиме OpenRouter API текст после выбранного способа распознавания отправляется в облачный сервис. Ответ приходит постепенно через Server-Sent Events (SSE) и сразу появляется в поле «Ответ ИИ». При включённом контексте вместе с запросом передаются завершённые текстовые обмены из истории текущей сессии. Общая вкладка «История» сохраняет запрос, полученные фрагменты ответа и итоговый статус; при ошибке или отмене уже полученный текст остаётся доступным.

В режиме OpenRouter Audio WAV отправляется в OpenRouter напрямую вместе с системным промптом и, если включён контекст, предыдущими ответами из истории. Модель получает инструкцию вернуть распознанный вопрос и ответ отдельными блоками; приложение показывает вопрос в поле текущего запроса и постепенно выводит ответ. Это распознавание выполняет сама аудиомодель, независимо от настройки «Способ распознавания речи». Возможны ошибки ключа, доступа, лимита запросов и кредитов, недоступности модели или провайдера, сети и обрыва потока. Бесплатные модели могут иметь ограничения доступности и количества запросов.

Итоговые файлы создаются в системном временном каталоге с именем `voiceassistant-<источник>-*.wav` и автоматически не удаляются. В режиме записи двух источников промежуточные файлы создаются в отдельном временном каталоге и удаляются после обработки. Если закрыть окно во время записи, приложение попытается остановить источник и завершить сохранение.

## История запросов и ответов

Нижняя часть окна содержит вкладки «Текущий запрос» и «История». Кнопка «Завершить и отправить в ИИ» расположена справа от «Остановить запись». На вкладке «Текущий запрос» кнопка «Распознать речь» находится справа от заголовка распознанного текста, а «Отправить в ИИ» — справа от состояния ИИ. Там же находятся редактируемый распознанный текст и последний ответ. Вкладка «История» сохраняет отправки как при ручной отправке, так и при нажатии «Завершить и отправить в ИИ». Новые записи появляются сверху сразу со статусом «Обрабатывается» и пополняются по мере генерации. После завершения они получают статус «Готово», «Ошибка» или «Отменено». При ошибке или отмене уже полученная часть ответа сохраняется; ошибка показывается рядом с ней.

В списке показаны время отправки и краткие фрагменты запроса и ответа. Выберите запись, чтобы прочитать и скопировать полные тексты в областях под списком. Кнопка «Очистить историю» удаляет все записи после подтверждения. Если в это время выполняется запрос, он продолжится, но удалённая запись не появится снова.

История хранится только в оперативной памяти и после закрытия приложения не восстанавливается. Если включён контекст диалога, завершённые записи из этой истории используются в последующих облачных запросах. Очистка истории удаляет и доступный контекст текущей сессии.

Сервис записи выполняет запуск и остановку источников в одном фоновом потоке. Для режима «Микрофон + системный звук» оба источника записываются отдельно, затем `AudioMixer` сводит их в итоговый WAV. В mono PCM 16 кГц WAV преобразуется только перед локальным распознаванием Whisper. Для удалённой транскрипции и OpenRouter Audio отправляется сохранённый WAV.

После локального или удалённого распознавания текст появляется в интерфейсе JavaFX. Пользователь может его исправить и отправить через `AiService.streamMessage(String, Consumer<String>, BooleanSupplier)` либо запустить автоматическую последовательность остановки, распознавания и отправки одной кнопкой. Для OpenRouter Audio автоматическая последовательность передаёт WAV в `AiService.streamAudio`. `AiServiceSelector` выбирает реализацию по режиму: `StubAiService`, `OpenRouterAiService` или `OpenRouterAudioAiService`.

`AiService` передаёт через callback только очередной новый фрагмент текста. Нормальный возврат метода означает успешное завершение; исключение сообщает об ошибке, `CancellationException` — об отмене. Переданный признак отмены позволяет остановить генерацию. Контракт не зависит от способа получения фрагментов. `StubAiService` формирует тестовый ответ локально, отдаёт его частями примерно по восемь символов с паузой 50 мс в фоновом потоке и регулярно проверяет отмену.

Контроллер складывает фрагменты в буфер и добавляет их в существующее поле JavaFX и запись истории пакетами примерно раз в 75 мс. Перед финальной сменой статуса остаток буфера обязательно переносится в ответ. Это ограничивает число обновлений JavaFX даже при множестве мелких фрагментов. Пустой ответ считается ошибкой. При закрытии приложения активная задача отменяется, Stub прекращает выдачу текста, а уже полученные фрагменты остаются в записи истории до завершения приложения. Отдельной кнопки отмены пока нет.

`OpenRouterAiService` отправляет распознанный текст в API и передаёт фрагменты ответа из SSE через общий callback. `OpenRouterAudioAiService` отправляет WAV и так же постепенно передаёт ответ. Облачные сервисы получают настройки из `AiSettings`, а ключи — из `AiSettingsService`. При включённом контексте `ConversationContextService` передаёт им снимок завершённых записей истории на момент отправки запроса.
