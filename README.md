# Voice Assistant

Десктопное JavaFX-приложение для записи аудио с микрофона, системного
звука Windows или обоих источников одновременно.

> **Статус на 10 октября 2026 года:** аудиомодуль реализован и проверен
> вручную; все три режима записи работают. Разработка временно
> приостановлена перед этапом Speech-to-Text.

## Технологии

-   Java 25
-   JavaFX 25.0.2
-   Maven / Maven Wrapper
-   Java Sound API --- захват микрофона
-   C++ / Windows WASAPI (loopback) --- захват системного звука
-   JNI --- вызов нативного кода из Java
-   CMake + Visual Studio C++ Build Tools --- сборка DLL
-   Windows 11 --- целевая среда текущей реализации

Spring Boot не используется: для текущего настольного JavaFX-приложения
он не требуется.

## Что реализовано

-   Выбор источника: `MICROPHONE`, `SYSTEM`, `BOTH`.
-   Асинхронный запуск и остановка записи без блокирования
    JavaFX-потока.
-   Запись микрофона через Java Sound API.
-   Запись системного аудио через нативную библиотеку
    `WasapiCapture.dll` (WASAPI loopback).
-   Совместная запись и объединение двух WAV-файлов через `AudioMixer`.
-   Уникальные итоговые WAV-файлы во временном каталоге ОС.
-   Промежуточные WAV-файлы режима `BOTH` создаются в отдельном
    временном каталоге и очищаются после обработки.
-   Обработка закрытия окна во время записи: блокировка элементов
    интерфейса, остановка источника и закрытие окна после завершения
    фоновой операции.
-   Кнопка «Отправить» присутствует, но фактическая
    отправка/распознавание ещё не реализованы.

Рекомендуемая структура после рефакторинга пакетов:

``` text
src/

    │       ├── VoiceAssistantApplication.java
    │       └── audio/

    │           │   └── MixedAudioSource.java
```

**Важно:** это согласованная *целевая* структура пакетов, а не

этапе классы аудиомодуля находились преимущественно в
`com.voiceassistant.service`, а `AudioSourceType` --- в
`com.voiceassistant.enums`. Переносить классы лучше через **Refactor →
Move (F6)** в IntelliJ IDEA, чтобы обновились `package` и `import`.

## Сборка и запуск Java-приложения

Нужны установленный **JDK 25** и настроенный **Maven Wrapper**. Команды
ниже выполняются из корня проекта.

На Windows в PowerShell:

``` powershell
.\mvnw.cmd clean compile
```

Для запуска используйте существующую конфигурацию запуска
`VoiceAssistantApplication` в IntelliJ IDEA. Конкретная Maven-команда
запуска зависит от плагинов в `pom.xml` и здесь не фиксируется,
поскольку `pom.xml` не проверялся.

Нативная DLL должна быть доступна Java-процессу; см. следующий раздел.

## Сборка нативной библиотеки C++ (WASAPI + JNI)

Нативный код отвечает за запись **системного звука Windows** через
WASAPI loopback. Java обращается к нему через JNI. Результат сборки ---
`WasapiCapture.dll`.

### 1. Установить инструменты

-   Visual Studio 2022 либо Visual Studio Build Tools с компонентом
    **Desktop development with C++** (MSVC и Windows SDK).
-   CMake.
-   JDK 25 (для заголовков `jni.h` и `jni_md.h`).

Проверьте инструменты в терминале разработчика Visual Studio:

``` powershell
cmake --version
cl
java -version
```

### 2. Настроить JAVA_HOME

В терминале, где запускается CMake, переменная `JAVA_HOME` должна
указывать на установленный JDK, а не на папку `bin`:

``` powershell
$env:JAVA_HOME = "C:\Path\To\jdk-25"
```

**Замените путь на фактический путь установки JDK.**

В `CMakeLists.txt` должны быть настроены поиск JNI-заголовков и сборка
shared-библиотеки. Типовой фрагмент (не точная копия CMake-файла
проекта):

``` cmake
cmake_minimum_required(VERSION 3.20)
project(WasapiCapture LANGUAGES CXX)

find_package(JNI REQUIRED)

add_library(WasapiCapture SHARED WasapiCapture.cpp)

target_include_directories(WasapiCapture PRIVATE ${JNI_INCLUDE_DIRS})
target_link_libraries(WasapiCapture PRIVATE ole32 uuid)
```

Имя C++-исходника и состав зависимостей необходимо сверить с реальным
`CMakeLists.txt`. Если текущий CMake-проект уже работает, **не заменяйте
его этим примером**.

### 3. Сконфигурировать и собрать DLL

Перейдите в каталог с нативным `CMakeLists.txt` (ниже он обозначен как
`native`; если у вас другое имя, замените путь):

``` powershell
cd native
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

При использовании другого генератора или версии Visual Studio
скорректируйте `-G`. Архитектура DLL должна соответствовать архитектуре
запущенной JVM (обычно x64).

Обычно DLL для Visual Studio generator окажется по пути вида:

``` text
native/build/Release/WasapiCapture.dll
```

Точный путь зависит от настроек `CMakeLists.txt` и генератора. Если
CMake настроен на другой каталог вывода, используйте его.

### 4. Сделать DLL доступной Java

В текущей реализации `SystemAudioSource` загружает `WasapiCapture.dll`
через JNI. Способ размещения зависит от фактического вызова загрузки:

**Если используется `System.loadLibrary("WasapiCapture")`:**

В VM options конфигурации запуска IntelliJ IDEA укажите папку с DLL:

``` text
-Djava.library.path=C:\absolute\path\to\native\build\Release
```

Здесь указывается **каталог**, а не файл DLL.

**Если используется `System.load("...")`:**

Передайте абсолютный путь непосредственно к `WasapiCapture.dll`;
`java.library.path` сам по себе не изменит этот путь.

Необходимо проверить актуальный `SystemAudioSource`, чтобы определить,
какой вариант используется в проекте. Скомпилированную DLL нельзя
подменять библиотекой другой архитектуры.

### 5. Проверить нативную запись

1.  Соберите DLL.
2.  Запустите JavaFX-приложение.
3.  Выберите `SYSTEM`.
4.  Включите воспроизведение звука в Windows.
5.  Нажмите «Начать запись», затем «Остановить запись».
6.  Убедитесь, что WAV создан и воспроизводится.

После изменения сигнатур JNI-методов в Java или C++ необходимо
обеспечить их совпадение и пересобрать DLL. После изменения
C++-реализации также пересоберите библиотеку и перезапустите приложение.

## Как работает запись

``` text
VoiceAssistantApplication
          |
          v
AudioRecordingService
          |
          +-- MICROPHONE --> MicrophoneAudioSource --> Java Sound --> WAV
          |
          +-- SYSTEM -----> SystemAudioSource -----> JNI/WASAPI --> WAV
          |
          +-- BOTH -------> MixedAudioSource
                              |          |
                              v          v
                           Microphone   System
                              |          |
                              +----+-----+
                                   |
                                   v
                               AudioMixer
                                   |
                                   v
                                WAV-файл
```

`AudioRecordingService` использует однопоточный `ExecutorService` для
последовательного выполнения операций запуска и остановки. Завершение
записи возвращает `CompletableFuture<Path>` с путём к итоговому WAV.

### Временные файлы

-   Итоговые WAV создаются через `Files.createTempFile(...)` с префиксом
    `voiceassistant-...`.
-   Для режима `BOTH` `MixedAudioSource` создаёт отдельную временную
    папку `voiceassistant-mix-...`, в которой временно хранятся записи
    микрофона и системы.
-   После успешного смешивания промежуточные файлы удаляются. При
    ошибках также выполняется попытка очистки.
-   **Итоговые WAV пока сохраняются** и автоматически не удаляются. На
    будущем этапе распознавания потребуется политика удаления после
    обработки.

### Закрытие окна во время записи

1.  JavaFX перехватывает нажатие крестика.
2.  Элементы интерфейса блокируются, отображается «Завершаем
    приложение...».
3.  В фоновом потоке вызывается `AudioRecordingService.close()`.
4.  Активный источник останавливается; для `BOTH` при штатной остановке
    выполняется смешивание.
5.  Сервис завершает executor и ожидает завершения до 30 секунд.
6.  JavaFX закрывает окно. При ошибке закрытия сообщение выводится в
    `System.err`.

**Ограничение:** таймаут 30 секунд не гарантирует принудительную
остановку нативного захвата. При ошибке сохранение корректного WAV не
гарантировано.
